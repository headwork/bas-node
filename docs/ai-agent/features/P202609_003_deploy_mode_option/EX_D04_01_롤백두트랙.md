# `[D04]` 롤백 두 트랙 — 분리해서 관리한다 (#P202609_003)

정본은 [spec.md](spec.md). 2026-09-23 보스 지시: *"배포시점에 롤백하고, 배포파일이 확정된 뒤
나중에 롤백하는 로직은 분리해서 관리해야 함."*

## 1. 왜 갈라야 하나

지금은 둘이 한 곳에 있다 — `rollback:` 스테이지가 **배포 실패 시 자동 실행**과
**`--rollback=N` 수동 실행** 양쪽에 쓰인다([deploy_shore.yaml:226-228](../../../design/template/deploy_shore.yaml#L226-L228)).
그래서 `rollback.bat` 이 `RB_MODE`(`consume` · `copy`)로 한 번 더 갈라져 있고,
여기에 배포 방식(copy · swap) 축이 더해지면 **한 스크립트에 축이 셋**이 된다.

**가르는 기준은 "확정됐는가"다.** 확정 전과 후는 되돌릴 대상도, 속도 요구도, 실행 주체도 다르다.

## 2. 두 트랙

| | **트랙 A — 배포중 원복** | **트랙 B — 확정 후 롤백** |
|---|---|---|
| 상태 | **미확정.** zip 도 유지파일도 확정 전 | **확정됨.** 며칠 뒤일 수도 있다 |
| 방아쇠 | 배포 실패 · 헬스체크 실패 | 사람 (`--rollback=N`) |
| 실행 | 파이프라인 자동 | 젠킨스 롤백 잡 · 수동 |
| 되돌릴 원본 | swap: `_org_<stamp>` / copy: **직전 확정 zip** | N번째 **확정 zip** |
| 사는 곳 | swap: `deploy.bat` 안 (ssh 왕복 없음) | `rollback.bat` |
| 속도 | 초 단위여야 한다 (서비스가 내려가 있다) | 분 단위 허용 |
| 끝난 뒤 | **확정하지 않는다.** 실패본은 `_failed_<stamp>` | 되돌린 판을 확정하지 않는다. 이력만 남긴다 |
| 유지파일 | 라이브 것 그대로 | 라이브 것 그대로 |

**유지파일은 어느 트랙에서도 되돌리지 않는다.** 기존 규칙 그대로다 —
*"롤백은 코드를 옛것으로 되돌릴 뿐 데이터는 현재 것이다."*

## 3. 트랙 A — 배포 방식에 따라 수단이 다르다

| 방식 | 실패 지점 | 원복 |
|---|---|---|
| swap | 스왑 도중·직후 | `_org_<stamp>` → 라이브 **역스왑.** 스크립트 안에서 끝난다 (현재 `:undo` 그대로) |
| swap | 헬스체크 실패 | 같음. `_org_` 가 아직 살아 있다(확정 전이므로) |
| copy | 복사 도중 | **라이브가 섞였다.** 직전 확정 zip 을 전개해 덮는다 |
| copy | 헬스체크 실패 | 같음 |

⚠️ **copy 모드의 첫 배포에는 직전 확정본이 없다.** 그 상태에서 복사가 중간에 깨지면 되돌릴 것이 없다.
→ **확정본이 하나도 없으면 copy 모드를 거부하고 멈춘다.** 라이브를 건드리기 전에 판정할 수 있다.
(운영 전환 시에는 swap 으로 한 번 돌려 확정본을 만든 뒤 copy 로 바꾼다.)

## 4. 트랙 B — 배포와 같은 길을 탄다

```
--rollback=N  →  이력에서 N번째 확정 zip 선택
              →  전개 -> (copy | swap) -> 시작 -> 헬스체크
```

**배포와 같은 경로다.** 되돌리는 길이 따로 있으면 그 길은 평소에 검증되지 않는다 —
정작 필요한 순간에 처음 도는 코드가 된다. 현재 yaml 의 TODO
(*"백업 폴더 대신 git commit id 로 재배포하는 방식을 추가할 예정"* [:225](../../../design/template/deploy_shore.yaml#L225))가
가리키던 방향이 이것이고, zip 확정이 그 절반을 이미 채운다.

`RB_MODE`(consume · copy)는 **사라진다.** 백업 폴더를 소비할지 복제할지는 폴더 백업 시절의 축이고,
확정 zip 은 전개해도 원본이 줄지 않는다.

## 5. 배치

| 트랙 | 자리 |
|---|---|
| A (swap) | `deploy.bat` `:undo` — 이미 있다. 그대로 둔다 |
| A (copy) | 파이프라인이 트랙 B 경로를 **N=1 자동**으로 호출 |
| B | `rollback.bat` 을 zip 전개 기반으로 다시 쓴다 |

트랙 A(copy)가 트랙 B 경로를 재사용하므로 **구현은 한 벌이고 방아쇠만 둘**이다.
"분리"는 코드를 두 벌로 만드는 것이 아니라 **판단의 경계를 가르는 것**이다 —
확정 전인가 후인가를 Node 가 정하고, 스크립트는 받은 원본으로 움직인다.
