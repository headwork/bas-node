# 6. 배포 스크립트 규약

원격·로컬 배포에서 **덩어리 작업을 맡는 스크립트**가 지켜야 하는 것.
저장소 원본은 [docs/design/template/windows/](../template/windows/) 에 있고,
서버에는 §8 배치대로 놓는다. 판단은 Node 가 하고 스크립트는 실행만 한다 —
경계는 [#P202609_002 `[D10]`](../../ai-agent/features/P202609_002_deploy_target_abstraction/spec.md) 이 정본이다.

**이 문서의 규약은 [test/scriptEncoding.test.js](../../../test/scriptEncoding.test.js) 가 강제한다.**
`npm test` 로 검사된다. 문서만 두면 지켜지지 않고, 어기면 **원격에서야 깨진다.**

---

## 1. 인코딩 — 파일과 코드페이지를 **일치**시킨다

2026-09-17 실측. `echo` 로 한글을 출력해 결과를 확인했다.

| 파일 인코딩 | 콘솔 코드페이지 | 결과 |
|---|---|---|
| CP949 | `chcp 949` | ✅ |
| UTF-8 | `chcp 65001` | ✅ |
| UTF-8 | `chcp 949` | ⛔ 깨짐 |
| CP949 | `chcp 65001` | ⛔ 깨짐 |

**일치하면 살고 엇갈리면 깨진다.** "UTF-8 이라서 깨진다"는 말은 틀렸다 —
UTF-8 파일은 `chcp 65001` 과 짝을 이루면 정상이다.

**BOM 은 영향이 없다.** cmd 는 BOM 을 보고 인코딩을 판단하지 않고, BOM 때문에 죽지도 않는다.
BOM 유무로 결과가 갈리지 않았다.

### 규약

```
① 기본은 ASCII 만 쓴다.                       ← 코드페이지와 무관해진다
② 한글이 꼭 필요하면 UTF-8 로 저장하고
   첫 줄에 `chcp 65001 > nul` 을 넣는다.
③ CP949(ANSI) 로 저장하지 않는다.
```

③ 의 이유는 세 가지다. git diff 가 깨져 보이고, 에디터가 UTF-8 로 재저장하는 순간 손상되며,
**서버 코드페이지가 949 가 아닌 곳(영문 Windows)에서 깨진다.**

> ⚠️ **가장 잡기 어려운 조합은 "CP949 파일 + `chcp 65001`"** 이다.
> 한글이 주석에만 있으면 출력이 없어 **한참 뒤에야 드러난다.**
> `D:\Deploy\jenkins\project_demo\server\check_param.bat` 이 지금 이 상태다
> (파일은 CP949 인데 2행이 `chcp 65001`). 주석만 한글이라 사고가 안 났을 뿐이다.

## 2. 줄바꿈 — `.gitattributes` 가 고정한다

```
*.bat  text eol=crlf
*.cmd  text eol=crlf
*.sh   text eol=lf
```

체크아웃 설정(`core.autocrlf`)에 맡기면 개발자 PC 마다 다른 바이트가 커밋되고,
그것이 **원격에서 조용히 오작동한다.** `.sh` 가 CRLF 면 `\r` 이 인자 끝에 붙어 경로가 어긋난다.

## 3. 인자 — 환경변수로 받는다. **기본값을 채우지 않는다**

위치 인자는 **순서를 틀리면 조용히 잘못 동작한다.** 배포 스크립트는 넘기는 값이 6~7개라
순서로는 감당이 안 된다.

```bat
if not defined DP_LIVE (
    echo [deploy] DP_LIVE is required
    exit /b 2
)
```

⚠️ **없는 값을 기본값으로 메우지 않는다.**

```bat
if not defined TAG_DEPLOY set TAG_DEPLOY=test    rem ⛔ 안 넘겨도 조용히 test 로 배포된다
```

`PipelineEngine.js` 가 같은 것을 경계한다 — *"기본 환경을 정하지 않는다. 'dev' 같은 이름을
코드가 들고 있으면 yaml 이 환경을 빠뜨렸을 때 **에러 없이** 그 환경으로 배포된다."*

> **예외 — `build` 계열은 위치 인자를 쓴다.** `build_dotnet_sample.bat` 은 `BuildStage` 와의
> 기존 계약이고 인자가 1~3개라 순서가 자연스럽다. 바꾸면 회귀만 생긴다.
> **새로 만드는 배포 계열(`deploy`·`rollback`·`webserver`)만 환경변수 규약을 따른다.**

### 목록을 넘길 때 — 구분자는 cmd 가 정한다

`DP_PRESERVE` 처럼 값이 여럿인 것은 **환경변수 하나에 이어서** 싣는다.
스크립트는 `for %%N in (%DP_PRESERVE%)` 로 쪼개는데, cmd 의 `for` 는
**공백·쉼표·세미콜론**에서 토큰을 가른다.

```yaml
preserve:
  - "uploads"        # ✅
  - "Temp"           # ✅
  - "my uploads"     # ⛔ 공백에서 갈라진다
  - "*.log"          # ⛔ for 가 경로로 펼친다
```

> ⚠️ **갈라져도 실패하지 않는다.** 갈라진 이름은 "이전 배포본에 없음" 으로 건너뛰어지므로
> **배포는 성공하고 운영 데이터만 사라진다.** 그래서 Node 가 조립할 때 막는다
> (`src/deploy/scriptArgs.js`).

## 4. 종료코드 — 이것이 Node 와의 계약이다

스크립트는 **성패를 종료코드로만 말한다.** 출력 문자열로 판정하지 않는다.

| 코드 | 뜻 |
|---|---|
| `0` | 성공. **"이미 원하는 상태"를 포함한다** |
| `1` | 알 수 없는 실패 |
| `2` | 입력이 없거나 잘못됨 |
| `3` | 권한 부족 |
| `4` | 대상 없음 (사이트·서비스·경로) |
| `5` | **실패했고 원복도 실패했다** — 라이브가 없는 상태. 사람이 고쳐야 한다 (`deploy.bat`·`rollback.bat`) |

> **원복에 성공해도 `0` 을 내지 않는다.** 서비스는 살아났지만 배포는 실패한 것이고,
> `0` 을 내면 **옛 빌드가 새 빌드로 배포된 것처럼 보고된다.** 원복 성공은 `1` 이다.

### 🔴 `1` 과 `5` 를 섞으면 안 되는 이유 — Node 의 마지막 판단이 여기 걸려 있다

덩어리를 스크립트에 넘긴 대가로 **Node 는 중간 지점을 보지 못한다.** 남은 판단이
"되돌릴 수 있는 상태인가" 하나이고, 그것을 종료코드로만 내린다.

| 코드 | 라이브 | 백업 | Node 가 하는 일 |
|---|---|---|---|
| `0` | 새 빌드 | 있다 | **무장** — health check 가 실패하면 되돌린다 |
| `1` | **이전 빌드로 살아 있다** | 없거나 소비됨 | 무장하지 않는다 |
| `2`·`3`·`4` | 그대로 | 없다 | 무장하지 않는다 |
| `5` | **없다** | 있다 (유일한 사본) | **무장** — 되돌리는 것 말고 답이 없다 |
| 그 외 | 모른다 (ssh 끊김 등) | 모른다 | **무장** — 못 되돌리는 쪽이 더 나쁘다 |

라이브가 없는데 `1` 을 내면 **되돌릴 수 있는 것을 못 되돌린다.**
반대로 라이브가 멀쩡한데 `5` 를 내면 롤백이 없는 백업을 찾다 멈추고,
*"누가 지웠는지 확인하십시오"* 라는 엉뚱한 말로 **진짜 사고를 소음에 묻는다.**

### 왜 메시지를 파싱하지 않나

`chcp` 는 바이트 해석을 맞출 뿐 **메시지의 언어를 바꾸지 않는다.**

| 서버 | `appcmd` 가 내는 말 |
|---|---|
| 한글 Windows | `사이트를 찾을 수 없습니다` |
| 영문 Windows | `The site does not exist` |

두 언어 패턴을 다 넣어도 제3 로캘이면 빠진다. 그래서 `webserver.bat` 은 메시지 대신
**`appcmd list ... /text:state` 로 상태를 조회해** 판정한다. 로캘에 의존하지 않는다.

### 반드시 종료코드를 넘겨준다

```bat
exit /b %ERRORLEVEL%
```

이게 없으면 마지막 명령의 코드가 새고, **"출력 마지막 줄로 판정"하던 옛 문제가 재현된다.**

> ⚠️ **batch 함정 — `%ERRORLEVEL%` 는 줄을 파싱할 때 확장된다.**
>
> ```bat
> call :ensure site Stopped || exit /b %ERRORLEVEL%    rem ⛔ 항상 0 을 반환한다
> ```
>
> `call` 이 **실행되기 전**의 값이 박힌다. 실패가 성공으로 보고된다. 이렇게 쓴다:
>
> ```bat
> call :ensure site Stopped
> if errorlevel 1 goto :propagate
> ...
> :propagate
>     exit /b %ERRORLEVEL%
> ```
>
> `goto` 로 점프한 뒤의 줄은 그 시점에 파싱되므로 진짜 코드가 실린다.

> ⚠️ **batch 함정 2 — 중첩 괄호 안의 `exit /b` 는 종료코드를 잃는다.**
>
> ```bat
> if /i "%RB_MODE%"=="copy" (
>     if not defined RB_TEMP (
>         echo [rollback] RB_TEMP is required
>         exit /b 2          rem ⛔ 메시지는 찍히는데 종료코드는 0 이다
>     )
> )
> ```
>
> 2026-09-17 `rollback.bat` 에서 실측했다. **로그에는 오류가 보이는데 호출자는 성공으로 받는다** —
> 가장 나쁜 조합이다. `goto` 로 평탄화한다:
>
> ```bat
> if /i not "%RB_MODE%"=="copy" goto :temp_checked
> if not defined RB_TEMP (
>     echo [rollback] RB_TEMP is required
>     exit /b 2
> )
> :temp_checked
> ```
>
> **괄호는 한 겹까지만 쓴다.** 두 겹이 필요해지면 그 자리가 `goto` 를 쓸 자리다.

## 5. `DRY_RUN` — 계획만 출력한다

```bat
if "%DRY_RUN%"=="1" (
    echo [deploy] DRY_RUN %VERB% %KIND% %WS_OBJ%
    exit /b 0
)
```

스크립트로 옮기면 `--dry-run` 이 명령을 못 보여준다. 그 관찰성을 스크립트가 직접 보전한다 —
`04_젠킨스_잡.md` 가 *"잡을 처음 걸 때는 `DRY_RUN` 으로 한 번 돌리고 변수 값을 눈으로 확인한다"* 를
운영 절차로 삼고 있다.

`DRY_RUN` 일 때는 **권한 검사보다 먼저 빠져나간다.** 관리자가 아니어도 계획은 볼 수 있어야 한다.

## 6. 파일명 — ASCII, 공백 없이

`웹서버 재기동.bat` 처럼 쓰지 않는다.

* **공백**은 따옴표를 부르고, 그 따옴표가 `ssh host "…"` 의 인용과 겹친다
  (`RemoteDeployMacroStage.js:273` 주석의 그 문제).
* **한글 파일명**은 전송·실행 경로마다 인코딩을 다시 맞춰야 한다.

## 7. 스크립트는 **한 벌**이다

원격용·로컬용으로 나누지 않는다. 배포서버에서 실행되는 것은 같고,
다른 것은 호출 경로(`node` 직접 vs `node → ssh`)뿐이다.

나누면 `IisControlStage` ↔ `RemoteDeployMacroStage.#iis()` 복붙 이중화가 그대로 재현된다 —
한쪽만 고치면 다른 쪽이 조용히 달라진다.

**로컬도 스크립트를 부른다.** 로컬에는 ssh 왕복이 없으니 Node 가 직접 `fs` 로 옮겨도
되지만, 그러면 스왑 순서가 두 곳에 살게 된다. 실제로 그랬고 **원격에만 있던 것과
로컬에만 있던 것이 서로 달랐다** — `preserve`(운영 데이터 이월)는 로컬에만 있었다.
합치니 그것이 원격에도 저절로 생겼다.

### 로컬과 원격에서 달라지는 것 — 둘뿐이다

| | 로컬 | 원격 |
|---|---|---|
| 경로 인용 | **감싼다** (`"…\deploy.bat"`) | **맨몸** — 이미 `ssh "…"` 안이다 |
| 값 전달 | 자식 프로세스 환경변수 | `set A=B&` 체인 |
| 값에 공백 | 쓸 수 있다 | **못 쓴다** (따옴표를 한 겹 더 못 씀) |

로컬에서는 **계약에 있는 키를 하나도 빠짐없이 적는다.** 빈 값은 Windows 에서 변수 삭제다.
빠뜨리면 부모 프로세스(젠킨스)에 같은 이름이 있을 때 그 값이 흘러든다 —
`WS_SKIP` 하나가 새어 들어오면 **웹서버를 세우지 않고 폴더만 갈아치운다.**

## 8. 배치 — **공용**과 **프로젝트별**을 가른다

가장 자주 틀리는 자리다. 공용 스크립트를 프로젝트 폴더에 복사해 두면
**프로젝트 수만큼 사본이 생기고**, 고칠 때 전부를 찾아다녀야 한다 —
이 저장소가 `IisControlStage` ↔ `RemoteDeployMacroStage.#iis()` 로 이미 겪은 병이다.

| 스크립트 | 프로젝트마다 다른가 | 자리 |
|---|---|---|
| `build_*.bat` · `copy_static_*.bat` | ✅ 빌드 방식이 프로젝트마다 다르다 | **프로젝트별** (`profile_dir`) |
| `deploy.bat` | ❌ 정지→백업→스왑→시작은 어디나 같다 | **공용 한 벌** |
| `webserver_*.bat` | ❌ **웹서버 종류별**이지 프로젝트별이 아니다 | **공용 한 벌** |

IIS 를 쓰는 프로젝트가 열 개여도 `webserver_iis.bat` 은 **파일 하나**다.

```
D:\Deploy\
  bas-deploy\                  도구 (프로젝트 무관)
    bas-deploy.js · bas-library.js · basDeploy.bat
    script\windows\            deploy.bat · webserver_iis.bat     ← 공용 한 벌
  <프로젝트>\                   예: hlngs
    config\                    = profile_dir
      deploy_*.yaml
      build_*.bat · copy_static_*.bat
      *.pubxml
    build\                     빌드 산출물
  jenkins\                     젠킨스 설치. 프로젝트 설정을 섞지 않는다
```

### yaml 변수

```yaml
deploy_root:  "D:/Deploy"
project_root: "${deploy_root}/<프로젝트>"
profile_dir:  "${project_root}/config"          # 프로젝트별 — 기존 변수
script_dir:   "${tool_home}/script/windows"     # 공용 — 생략하면 도구 옆을 본다
```

원격 전달 경로는 **별도 변수를 두지 않는다.** `${upload_path}/_scripts/` 로 보내면
`upload_path` 가 이미 프로젝트별이라 격리가 따라온다.

### 전송 — 사람은 한 곳에만 두고, 원격에는 도구가 민다

| 단계 | 누가 | 어디에 |
|---|---|---|
| ① 배치 | **사람** (한 번) | 도구 서버 `${tool_home}\script\windows\` |
| ② 전송 | **도구** (배포마다) | 배포서버 `${upload_path}\_scripts\windows\` |

배포서버에 손으로 올려 둘 필요가 없다. `remote_deploy` · `remote_rollback` 이
**웹서버를 멈추기 전에** `${script_dir}` 의 `*.bat` 을 전부 scp 로 보낸다.

**매번 덮어쓴다.** "이미 있으면 건너뛴다" 를 하지 않는 이유는 옛 판이 남는 쪽이 더 위험해서다 —
§4 의 종료코드 표가 바뀌면 Node 가 실패를 성공으로 읽고, 옛 프로세스가 새 파일을 서비스한다.
파일 서너 개라 매번 보내는 값이 싸다.

**산출물 zip 에 넣지 않는다.** zip 은 임시폴더에 풀려 **그대로 라이브가 되므로**
배포 스크립트가 서비스 폴더에 남는다. 그래서 전송을 따로 한 번 더 한다(ssh 왕복 +1, scp +1).

```yaml
sync_scripts: false     # 배포서버에 직접 배치했을 때만. 기본은 true(전송함)
```

> ⚠️ **전송 실패는 배포 시작 전에 난다.** 폴더가 없거나 비어 있으면 업로드도 하기 전에 멈춘다 —
> 원격은 손대지 않은 상태다. 이것을 웹서버 정지 단계에서 만나면 **서비스만 멈춘 채로 끝난다.**

> ⚠️ **`upload_path` 에 공백을 쓰지 않는다.** 원격 명령은 `ssh host "…"` 안에 통째로 들어가
> 따옴표를 한 겹 더 쓸 수 없고, 공백이 있으면 경로가 **조용히 잘린다.** 도구가 즉시 멈춘다.

## 9. 웹서버 어댑터 명명 — `webserver_<type>.bat`

`deploy.bat` 은 **웹서버를 모른다.** `WS_TYPE` 으로 파일을 골라 부를 뿐이다.

```bat
set "WS_ADAPTER=%SCRIPT_DIR%webserver_%WS_TYPE%.bat"
if not exist "%WS_ADAPTER%" exit /b 4
```

→ **nginx 를 붙이려면 `webserver_nginx.bat` 을 옆에 놓으면 된다. `deploy.bat` 은 열지 않는다.**
그것이 이 구조의 목적이다.

어댑터가 지켜야 하는 것은 §4 의 종료코드 표 하나다. `WS_NAME` 은 공통이고,
그 밖의 `WS_*` 변수(IIS 의 `WS_POOL` 등)는 `deploy.bat` 이 해석하지 않고 **그대로 상속시킨다.**

| 어댑터 | 상태 |
|---|---|
| `webserver_iis.bat` | 구현됨 |
| `webserver_nginx.bat` · `webserver_apache.bat` · `webserver_tomcat.bat` | 미구현 (#P202609_002 2단계) |

> ⚠️ **미등록 타입은 조용히 건너뛰지 않고 `4` 로 멈춘다.** 건너뛰면 폴더만 갈아치우고
> **옛 프로세스가 새 파일을 서비스한다.**
