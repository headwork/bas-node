## 공통 개념

### 실행

```
node src/deploy/deploy-cli.js --yaml=<경로> [--params='{"environment":"qa"}'] [--dry-run]
                              [--mode=copy|swap] [--only=<그룹>] [--rollback=N]
```

`--dry-run` 은 **아무것도 실행하지 않고** 해석된 변수와 단계 계획만 출력한다.
등록되지 않은 스테이지가 있으면 경고한다. 실행 전 확인용이다.

`--mode` 는 이번 실행에만 배포 방식을 강제한다(아래 [배포 방식](#배포-방식--copy--swap)).
`--rollback=N` 은 배포하지 않고 **N번째 확정 빌드로 되돌린다**(1 = 직전 확정 배포).

### 이번 실행이 어떻게 도는가 — `[이번 배포]`

실행마다 **행동을 가르는 설정만** 한 블록으로 먼저 찍는다. 나중에 로그만 보고 판정할 수 있어야 한다.

```
[이번 배포]
  환경      qa
  배포방식  swap  (--mode)          <- 출처까지. YAML(스테이지) · YAML(변수) · 기본값
  대상      원격 221.139.50.188:9222
  라이브    D:/Deploy/MFM.Shore_QA
  백업      D:/HLNGS/backup\MFM.SHORE_QA  (보관 3판)
  브랜치    deploy/qa
  압축      true
  공지      telegram=true confluence=false
  그룹      deploy
  DRY RUN   아니오
```

전체 변수 목록(`Merged Context Variables`)과 다른 점이 둘이다. **해석이 끝난 값**을 적고,
**스테이지 설정 안에 있는 값도 포함한다.** 2026-09-23 에 `deploy_mode` 가 전체 목록에 없다는
이유로 방식을 잘못 읽은 일이 있었다 — 그 값은 스테이지 설정 안에 있었다.

### 배포 방식 — `copy` · `swap`

| | 하는 일 | 강한 곳 | 약한 곳 |
|---|---|---|---|
| `copy` (기본) | 정지 → 라이브에 덮어쓰기(robocopy) → 시작 | 폴더가 열려 있어도 배포된다 | 옛 파일이 남는다. 실패하면 라이브가 섞인다 |
| `swap` | 임시폴더 준비 → 정지 → 폴더 교체 → 시작 | 정지 구간이 짧다. 지워진 파일이 사라진다 | 폴더가 잠겨 있으면 그 자리에서 막힌다 |

`deploy_mode` 로 정하고 `--mode` 가 덮는다. 생략하면 `copy` 다.

> **clean 빌드와 누적 빌드** — `swap` 은 배포본을 통째로 갈아끼우므로 **빌드 산출물에 없는 파일은 사라진다.**
> 소스에서 지운 DLL 이 라이브에서도 없어진다는 뜻이고, 대개 그것이 원하는 바다.
> 반대로 `copy` 는 덮어쓰기만 하므로 옛 파일이 남는다(`/MIR` 을 쓰지 않는다 — 운영 데이터까지 지운다).
> 빌드를 clean 으로 하느냐 누적하느냐에 따라 결과가 달라지는데, **도구는 이것을 검사하지 않는다.**
> 누적 빌드 + `copy` 로 쌓인 것을 한 번 쓸어내려면 `--mode=swap` 으로 한 번 돌린다.

### 변수 조립 순서

뒤가 앞을 덮는다.

1. YAML 루트의 단순 설정값 (`git_url`, `deploy_path` 등)
2. `variables:` 블록
3. `--params` 외부 파라미터
4. `target[environment]` 프로파일 — 1~3 을 기준으로 먼저 치환한 뒤 덮어쓴다
5. `--params` 재적용 (외부 파라미터가 끝까지 최우선)

정의되지 않은 프로파일을 지정하면 **즉시 실패한다.** 조용히 빈 변수로 진행하면
스테이지가 엉뚱한 경로에 배포하기 때문이다.

### 민감 정보

`${env.VAR}` 로 `process.env` / `.env` 값을 주입한다.
치환된 값은 **로그 출력 시 마스킹**된다(`***(masked)`). URL 에 박힌 자격증명도 가린다.

> ⚠️ Git 서버가 **Bonobo Git Server** 인 경우 API 키 개념이 없다.
> `git_url` 에 자격증명을 넣으면 Windows 자격증명 관리자(GCM)나 Jenkins 에 등록된
> 정상 자격을 **덮어써서 인증이 실패한다.** 자격증명 없는 URL 을 쓰고 실행 주체에게 맡긴다.

### 스테이지 목록

| 스테이지 | 역할 |
|---|---|
| `git_sync` | 최초 clone, 이후 원격 브랜치에 강제로 맞춤(fetch → `checkout -f -B`). 변경 분류의 기준은 **이 환경의 마지막 성공 배포 커밋** |
| `static_patch` | 정적 파일만 바뀐 배포. 바뀐 파일만 라이브에 덮어쓰기(`patch.bat`), 웹서버는 죽어 있을 때만 시작 |
| `c#_build` | 빌드 (`cmd` 로 명령 지정) |
| `archive` | 배포 산출물 압축 (`<name>_<yyyyMMdd_HHmmss>.zip`) |
| `extract` | 압축 해제 (`tar -xf` — gz/zip 자동 판별) |
| `local_deploy` | 유지파일 백업·이월(정지 전) → 정지 → 복사 또는 스왑 → 시작. **정리하지 않는다** |
| `remote_deploy` | 같은 일을 ssh 너머로. 스크립트 동기화 → 업로드 → 해제 → `deploy.bat` |
| `confirm` | **확정.** 헬스체크 **뒤**에 놓는다 — 이름 변경·삭제가 전부 여기 모인다 (아래) |
| `local_rollback` · `remote_rollback` | 확정 빌드(zip) 또는 스왑이 남긴 옛 라이브로 복구 |
| `backup_cleanup` | 백업 보관 정책 단독 실행 |
| `iis_control` | IIS 사이트/앱풀 start·stop |
| `fs_rename` | 디렉터리 이름 변경 (EXDEV 폴백 포함) |
| `health_check` | HTTP 상태/본문 확인. `health_url` 이 없으면 건너뜀 (`if: server_restarted` 로 재시작했을 때만 부른다) |
| `other_server` | scp 업로드 + 원격 명령 |
| `confluence` | 문서 갱신 |
| `sync` · `build` · `upload` | 임의 명령 실행 |

### 확정과 백업 — 되돌릴 곳은 zip 하나다

**한 배포 = 한 스탬프**(`YYYYMMDD_HHMMSS`). 그 배포가 만드는 것들이 스탬프로 묶인다.

```
<라이브>_temp_<스탬프>        스테이징 (압축해제 결과)          라이브 옆
<라이브>_org_<스탬프>         스왑으로 밀려난 옛 라이브          라이브 옆, 헬스체크까지
<백업폴더>\<라이브>_preserve_<스탬프>\   유지파일 백업 겸 이월 원본
<백업폴더>\_builds\<라이브>_<스탬프>.zip 확정 빌드 = **롤백의 원본**
```

**백업 폴더는 `backup_root` 밑에 웹서버 이름으로 한 겹 판다** — `<backup_root>\<web_server_name>\`.
이름 규칙만으로도 도구끼리 섞이지는 않지만, 한 폴더에 여러 프로젝트의 백업과
다른 도구의 산출물이 함께 있으면 **사람이 그 폴더를 열었을 때** 뭘 지워도 되는지 판단이 안 선다.
그 판단은 대개 급할 때 해야 한다.

**라이브 폴더 사본은 뜨지 않는다.** 되돌릴 곳은 확정 zip 하나이고, 롤백은 그 zip 을 다시 전개하므로
**배포와 같은 길**을 탄다 — 비상시에만 도는 코드가 아니라 매일 도는 코드다.
되돌릴 곳이 없는 상태(첫 배포·이력 없음)는 고장이 아니라 정상이고, 롤백이 그렇게 말한다.

`confirm` 이 헬스체크 **뒤**인 이유: 그 전까지 라이브 옆에 남아 있는 것들(`_org_`·`_temp_`)이
곧 복구 수단이다. 앞당기면 헬스체크가 실패했을 때 **되돌릴 판을 이미 치운 뒤**가 된다.
확정이 실패해도 배포를 뒤집지 않는다 — 여기까지 왔다는 것은 서비스가 이미 정상이라는 뜻이다.

보관은 `backup.keep_count` 한 값이 **유지파일 백업·확정 zip에 함께** 걸린다.
이 개수가 곧 `--rollback=N` 의 상한이다. 남기지 않은 것은 되돌릴 수 없다.

### 롤백 두 트랙 — 기준은 "확정됐는가"

구현은 한 벌이고 방아쇠만 둘이다.

| | 언제 | 원본 | 속도 |
|---|---|---|---|
| **트랙 A** | 배포 중 실패 (헬스체크 등) — 파이프라인이 자동 | `swap`: `_org_` 역스왑 / `copy`: 직전 확정 zip | 역스왑은 초 단위 |
| **트랙 B** | `--rollback=N` — 사람이 판단 | N번째 확정 zip | 전개 포함 |

되돌리는 것은 **코드**다. `preserve` 목록의 파일은 **현재 라이브에서** 가져온다 —
업로드·설정은 지금 것이 맞다.

### 조건부 실행

스테이지에 `if:` / `unless:` 를 붙이면 컨텍스트 변수 값에 따라 건너뛴다. 이름 하나 또는 목록을 받는다.

```yaml
- static_patch:
    if: changed_static_only                         # 참일 때만 실행
- build:
    unless: changed_static_only                     # 참이면 건너뜀
- local_deploy:
    unless: [deploy_remote, changed_static_only]    # 하나라도 참이면 건너뜀
```

값이 `false` · `0` · 빈 문자열이면 거짓이다. 조건은 `--dry-run` 계획에 함께 표시된다.
자세한 규칙은 [정적 파일 빠른 배포](03_정적파일_빠른배포.md#조건부-실행).

### 실패 처리

파이프라인이 실패하면 `rollback:` 이 실행된다. 정의는 세 형태를 받는다.

```yaml
rollback:                          # 1) 스테이지 목록
  - local_rollback: {}

rollback:                          # 2) 원격 스크립트
  script_dir: "D:/scripts"
  rollback_cmd: "rollback.bat"

rollback: "restore.bat"            # 3) 단일 명령
```

어느 형태에도 맞지 않으면 조용히 넘어가지 않고 CRITICAL 로그를 남긴다.
**롤백 실패는 원래 배포 에러를 덮지 않는다** — 삼키고 로그만 남긴 뒤 원본 에러를 전파한다.
